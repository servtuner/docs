servtuner never assumes that a network is encrypted and never guesses. You make two choices:

| Question                     | Setting                                 | Values                                                            |
| ---------------------------- | --------------------------------------- | ----------------------------------------------------------------- |
| Is the connection encrypted? | `enabled`, per connection               | `true` verifies the server over `https://`. `false` is plain HTTP |
| Does the server ask for one? | `clientAuth` on a server servtuner runs | `required`, `optional` (verify one if it is sent) or `none`       |

Each servtuner component has one certificate and presents it on every connection with TLS, so you do not choose client certificates connection by connection. The server decides whether to ask for one: servtuner's API by `clientAuth`, and other servers by their own configuration.

servtuner's own connections default to TLS, with client certificates required. A connection without TLS takes no certificate settings, and a connection with TLS needs an `https://` URL. Contradictions are errors. There is no option to skip verification.

## Prerequisites

- With TLS, cert-manager with an issuer, or `kubernetes.io/tls` Secrets.

## Steps

### servtuner's own connections

Set the default with `tls.enabled`, and override a connection under `tls.connections` with `true` or `false` when it differs:

| Name              | Connection                    | Note                    |
| ----------------- | ----------------------------- | ----------------------- |
| `ingressApi`      | Ingress or gateway to the API |                         |
| `benchApi`        | bench to the API              | Must equal `ingressApi` |
| `postgres`        | API to Postgres               | See `postgres.auth`     |
| `objectStore`     | API and bench to S3           |                         |
| `benchPrometheus` | bench to Prometheus           |                         |

```yaml
tls:
  enabled: true
  clientAuth: required
  source: cert-manager
  certManager:
    issuerRef: { kind: ClusterIssuer, name: your-issuer }
  connections:
    benchPrometheus: false
```

Installed with the helmfile, `issuerRef` defaults to servtuner's private CA, `servtuner-ca` (see [components](/deployment/components/)); name your own issuer only to replace it.

`tls.clientAuth` is the API's own policy. With `required` or `optional`, bench presents its certificate to the API. With `optional`, a client without a certificate gets in on its sign-in or run token alone, and a certificate that is sent is still verified. With `none`, the API asks for no certificate. The two API connections share one listener, so they must agree.

### Postgres sign-in

How the API signs in to Postgres is an authentication setting, `postgres.auth`:

| `postgres.auth`         | Sign-in                                                                         |
| ----------------------- | ------------------------------------------------------------------------------- |
| `certificate` (default) | The API's certificate, whose common name is the database user. Needs TLS        |
| `password`              | The generated password (CloudNativePG) or `postgres.external.passwordSecretRef` |

With TLS off on the `postgres` connection, set `postgres.auth: password`. A password over a TLS connection is also allowed.

With `source: secret`, name a Secret for each component. The bench Secret must exist in the runs namespace.

### RunSpec connections

A target is someone else's server and may need its own certificate, so a RunSpec names one. Set `target.tls`, each `upstreams[].tls` and `prometheus.tls`:

```yaml
tls:
  enabled: true
  clientCert: { secretRef: { name: servtuner-client } } # optional: present this certificate
  caSecretRef: { name: vllm-ca } # optional: a private CA that signed the server
```

Only the `ca.crt` of `caSecretRef` is read. Plain HTTP is `tls: { enabled: false }`.

### Private CAs

Each pod combines system CAs with the private CA and sets `SSL_CERT_FILE`. Do not point `SSL_CERT_FILE` at a private CA alone, because that replaces the system roots.

## When to turn TLS off

Turn TLS off on a connection only when something else encrypts it, such as a service mesh or a CNI with encryption, or for local testing. servtuner cannot check that claim. Every run records each connection's settings, so you can see what it relied on.

## Managed Servers

Managed Servers serves plain HTTP by default. `{ enabled: true }` gives each target its own server certificate. Client certificates are not offered yet.

## Upgrade from servtuner 0.1

servtuner 0.1 named one of three modes per connection. 0.2 rejects them and names the replacement.

| servtuner 0.1                       | servtuner 0.2                                                    |
| ----------------------------------- | ---------------------------------------------------------------- |
| `apiVersion: servtuner.dev/v1`      | `apiVersion: servtuner.dev/v2`                                   |
| `tls: { mode: mtls, secretRef: S }` | `tls: { enabled: true, clientCert: { secretRef: S } }`           |
| `tls: { mode: tls }`                | `tls: { enabled: true }`                                         |
| `tls: { mode: platform }`           | `tls: { enabled: false }`                                        |
| Chart `tls.mode: mtls`              | `tls.enabled: true` with `tls.clientAuth: required`              |
| Chart `tls.hops.postgres: platform` | `tls.connections.postgres: false` with `postgres.auth: password` |
| `--api-tls-mode mtls`               | `--api-tls true`, with `--tls-cert-file` and `--tls-key-file`    |
| Launcher `tls_mode: platform`       | `tls: false`                                                     |

Saved targets, managed targets and schedules are converted when the API upgrades its database. Runs from 0.1 keep their original RunSpecs, which servtuner still reads.

## Verify

`servtuner validate` rejects contradictory RunSpecs, and Helm rejects contradictory values. After a run, **Config** shows each connection as TLS with a client certificate, TLS, or no TLS.
