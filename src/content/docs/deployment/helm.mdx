servtuner installs as five Helm releases: cert-manager, CloudNativePG, Envoy Gateway, kube-prometheus-stack and servtuner itself, plus an issuer and a Gateway you add with two short manifests (step 4). Each prerequisite is its upstream chart, unmodified, in its own release and namespace. You upgrade and roll back each one on its own, and skip any your cluster already runs. Each release's deploy bundle holds the helmfile that declares all five and installs them in order, pinned to that release.

For a cluster with no internet access, follow [air-gapped installs](/deployment/air-gapped/) instead. It uses the same helmfile.

## Prerequisites

- Kubernetes 1.35 or newer, and a default StorageClass. For real benchmarks, GPU nodes with the NVIDIA device plugin.
- `helm` 3 or 4 and `helmfile` v1.8.5. `helmfile sync` needs no Helm plugin; `apply` and `diff` need helm-diff.
- Nodes that can pull from `ghcr.io`, where servtuner's images are published. Without internet access, follow [air-gapped installs](/deployment/air-gapped/).
- ReadWriteMany storage for several nodes, or an S3-compatible store. See [storage](/deployment/storage/).

## Steps

### 1. Download the deploy bundle

Download `servtuner-deploy-<version>.tar.gz` from the [release](https://github.com/servtuner/servtuner/releases), check it, and unpack it:

```sh
VERSION=<version>
base=https://github.com/servtuner/servtuner/releases/download/v$VERSION
curl -fsSLO "$base/servtuner-deploy-$VERSION.tar.gz" -O "$base/checksums.txt"
sha256sum --check --ignore-missing checksums.txt
tar -xzf "servtuner-deploy-$VERSION.tar.gz"   # writes deploy/
```

The chart in it defaults to the release's images, `ghcr.io/servtuner/servtuner-*:<version>`. To check signatures, see [verify downloads](/deployment/verify/).

### 2. Create Secrets first

No secret goes in a values file, the helmfile or the release. Values name a Kubernetes Secret, and you create it before the install.

| Secret                                                    | Where                               | Keys                           | When                                          |
| --------------------------------------------------------- | ----------------------------------- | ------------------------------ | --------------------------------------------- |
| A registry pull secret (`kubernetes.io/dockerconfigjson`) | Every namespace the releases run in | `.dockerconfigjson`            | Your registry needs a login to pull           |
| TLS certificates (`kubernetes.io/tls`)                    | servtuner's namespace               | `tls.crt`, `tls.key`, `ca.crt` | `tls.source: secret` instead of cert-manager  |
| Object store keys for model weights                       | The managed vLLM's namespace        | Your names                     | Weights streamed from S3 without pod identity |
| A Hugging Face token                                      | The managed vLLM's namespace        | `token`                        | Gated models from Hugging Face or a mirror    |

The chart generates the first-admin setup token itself. See [authentication](/deployment/authentication/).

### 3. Install the prerequisites

Install every release but servtuner first, so the issuer and the Gateway in the next step have their CRDs:

```sh
helmfile -f deploy/helmfile.yaml.gotmpl -e eks --selector 'name!=servtuner' sync   # or -e kind
```

### 4. Add an issuer and a Gateway

servtuner 0.1's helmfile installs cert-manager and Envoy Gateway, but no issuer and no Gateway. Add these two, or skip either if you already run your own (see [components](/deployment/components/)).

servtuner's private CA, a self-signed root and the `servtuner-ca` ClusterIssuer:

```yaml title="servtuner-issuer.yaml"
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: servtuner-selfsigned
spec:
  selfSigned: {}
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: servtuner-ca
  namespace: cert-manager
spec:
  isCA: true
  commonName: servtuner-ca
  secretName: servtuner-ca
  duration: 87600h
  privateKey: { algorithm: ECDSA, size: 256 }
  issuerRef: { name: servtuner-selfsigned, kind: ClusterIssuer, group: cert-manager.io }
---
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: servtuner-ca
spec:
  ca:
    secretName: servtuner-ca
```

A GatewayClass and the Gateway servtuner's routes attach to, listening for plain HTTP on port 80:

```yaml title="servtuner-gateway.yaml"
apiVersion: gateway.networking.k8s.io/v1
kind: GatewayClass
metadata:
  name: servtuner
spec:
  controllerName: gateway.envoyproxy.io/gatewayclass-controller
---
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: servtuner
  namespace: servtuner
spec:
  gatewayClassName: servtuner
  listeners:
    - { name: http, protocol: HTTP, port: 80, allowedRoutes: { namespaces: { from: Same } } }
```

On a cluster without a load balancer, such as kind, a LoadBalancer Service never gets an address and the Gateway never becomes ready. Give the proxy a ClusterIP Service instead: add this to the file, and add `parametersRef: { group: gateway.envoyproxy.io, kind: EnvoyProxy, name: servtuner-cluster-ip, namespace: envoy-gateway-system }` under the GatewayClass's `spec`.

```yaml
---
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: EnvoyProxy
metadata:
  name: servtuner-cluster-ip
  namespace: envoy-gateway-system
spec:
  mergeType: StrategicMerge
  provider:
    type: Kubernetes
    kubernetes:
      envoyService:
        type: ClusterIP
```

Apply both, and wait until they are ready:

```sh
kubectl create namespace servtuner
kubectl apply -f servtuner-issuer.yaml -f servtuner-gateway.yaml
kubectl wait --for=condition=Ready clusterissuer/servtuner-ca --timeout=2m
kubectl -n servtuner wait --for=condition=Programmed gateway/servtuner --timeout=3m
```

Terminate browser TLS in front of the Gateway, or add an HTTPS listener with your certificate.

### 5. Write your site values

Copy `deploy/helmfile/site-values.example.yaml` to `deploy/site-values.yaml`. Every value of the chart may go there; these are the ones every site decides. On kind, the `kind` environment reads `deploy/helmfile/kind-values.yaml` instead of `deploy/site-values.yaml` in 0.1, so put your values in that file.

<Tabs syncKey="tls">
  <TabItem label="mTLS (default)">

```yaml title="deploy/site-values.yaml"
tls:
  mode: mtls
  source: cert-manager
  certManager:
    issuerRef: { kind: ClusterIssuer, name: servtuner-ca }
gateway:
  enabled: true
  hostname: servtuner.example.internal # localhost on kind
  parentRefs: [{ name: servtuner }]
storage:
  file:
    pvc: { create: true, accessMode: ReadWriteMany, size: 100Gi }
rbac:
  bench:
    targetNamespaces: [inference]
```

  </TabItem>
  <TabItem label="Platform encryption">

```yaml title="deploy/site-values.yaml"
tls:
  mode: platform
gateway:
  enabled: true
  hostname: servtuner.example.internal # localhost on kind
  parentRefs: [{ name: servtuner }]
storage:
  file:
    pvc: { create: true, accessMode: ReadWriteMany, size: 100Gi }
rbac:
  bench:
    targetNamespaces: [inference]
```

`platform` states that your network encrypts this traffic. servtuner cannot check that.

  </TabItem>
</Tabs>

On kind, use `accessMode: ReadWriteOnce` and a small `size`, such as `1Gi`; kind's storage is ReadWriteOnce only.

### 6. Install

```sh
helmfile -f deploy/helmfile.yaml.gotmpl -e eks sync     # or -e kind
kubectl -n servtuner wait --for=condition=Ready pod -l app.kubernetes.io/component=api --timeout=10m
```

To use your own image registry, add `--state-values-set registry=registry.example:5000`. With a pull secret, also add `--state-values-set 'imagePullSecrets={regcred}'`.

### 7. Sign in

Open the hostname you set. On kind, forward a local port to the Gateway and open `http://localhost:8080`:

```sh
kubectl -n envoy-gateway-system port-forward \
  "$(kubectl -n envoy-gateway-system get svc -l gateway.envoyproxy.io/owning-gateway-name=servtuner -o name)" 8080:80
```

Create the first admin with the setup token, and sign in. See [authentication](/deployment/authentication/). If the API answers 503 in the first seconds after the install, the Gateway is still picking it up: try again.

## Skip a prerequisite

Turn off any prerequisite your cluster already runs:

```sh
helmfile -f deploy/helmfile.yaml.gotmpl -e eks \
  --state-values-set install.certManager=false,install.prometheus=false sync
```

servtuner then uses yours ([components](/deployment/components/) lists what each needs): cert-manager's CRDs, the CloudNativePG operator (or an external Postgres with `postgres.mode: external`), your Gateway API controller or an Ingress, and your Prometheus (`prometheus.url` in your site values).

When your cluster already runs every prerequisite, install the chart alone from the registry:

```sh
helm install servtuner oci://ghcr.io/servtuner/charts/servtuner --version <version> \
  --namespace servtuner --create-namespace -f site-values.yaml
```

## Expose it

<Tabs>
  <TabItem label="Gateway API">

`gateway.enabled` renders two HTTPRoutes on one hostname: the UI, and the API under `<basePath>/api`. In `mtls`, an Envoy `Backend` presents the chart's client certificate to the API and a `BackendTLSPolicy` checks the API's name. Install Envoy Gateway with `enableBackend`.

  </TabItem>
  <TabItem label="Ingress">

`ingress.enabled` renders the same two routes as Ingresses for ingress-nginx, which is retired upstream: prefer the Gateway API for new installs. In `mtls`, the API Ingress verifies the API with the chart's certificate. `ingress` and `gateway` are exclusive.

  </TabItem>
</Tabs>

For a subpath, set `frontend.basePath`. Terminate browser TLS at the gateway or ingress. `networkPolicy.enabled` (the default) lets only the ingress controller or gateway (`networkPolicy.ingressController`) and bench Jobs reach the API, and nothing reach a bench pod. It needs a CNI that enforces NetworkPolicy.

## Permissions

The API manages Jobs, ConfigMaps and Secrets in the runs namespace. bench reads workloads in `rbac.bench.targetNamespaces` and nodes cluster-wide. Nothing is granted for managed targets until you list `rbac.tuning.namespaces`.

## Upgrade

Run `helmfile … sync` again with the new versions. The API migrates its database on start. Each release is an ordinary Helm release, so `helm history` and `helm rollback` work on each. To upgrade only servtuner and hold the prerequisites, add `--selector name=servtuner`.

## Verify

```sh
helmfile -f deploy/helmfile.yaml.gotmpl -e eks list   # the releases and their versions
kubectl -n servtuner get pods
kubectl -n servtuner get certificates
```

Then save a target and run a connection check.
