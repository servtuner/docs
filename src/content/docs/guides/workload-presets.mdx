A preset is one exact request mix. Runs with the same preset always have the same workload hash, so they can be compared. The token columns are means; [workloads and token lengths](/concepts/workloads/) explains how runs meet them.

## Prerequisites

- The `loadgen` engine. Every current preset lists it as its only engine.

## Steps

1. In **New run**, choose a preset. servtuner fills in its suggested SLOs and a starting ladder.
2. Or reference it in the RunSpec:

{/* schema: runspec */}

```yaml title="preset.yaml"
apiVersion: servtuner.dev/v1
kind: RunSpec
name: chat-short
target:
  type: openai-compatible
  endpoint: http://localhost:18000/v1
  model: mock-model
  tls: { mode: platform }
engine: { type: loadgen }
workload:
  preset: chat-short@1
  streaming: true
load:
  stages:
    - { rate: 4, duration: 60s }
slos: { ttft_p95: 500ms, itl_p95: 50ms }
```

Do not combine a preset with `dataset` or `conversation`. To change anything, write the workload out. bench never applies a preset's suggested SLOs, so state yours.

:::note
Suggested rates are handwritten starting points for named GPU classes. They are not measured capacity.
:::

## Verify

`servtuner presets` prints the catalog built into your binary. After a run, `spec.resolved.json` contains the expanded workload and the preset's name and version.
